# 0.1.58 修复：粘贴图文后内容空白

来源：老板 2026-11-23 02:55 ET 真机反馈。从聊天应用复制一段文字，点「粘贴收纳」后条目判成「图文」，标题显示「图文」，点开详情是一整块白色。

## 根因（mind 已在本机复现）
1. Chrome 和 Electron 应用（包括 Grok Bot、飞书桌面版）往剪贴板写 HTML 时，开头带 `<meta charset='utf-8'>`。
2. `electron/inbox-store.js` 的 `sanitizeHtml` 第一条正则把 `meta|link|base|form` 和 `script|style` 一样按成对标签删除，形式是 `<tag …>…(</tag>|$)`。`meta`、`link`、`base` 没有结束标签，所以会一直删到字符串结尾，正文被整段清空。
   复现：`sanitizeHtml("<meta charset='utf-8'><p>你好</p>")` 返回 `""`。
3. `classifyClipboard` 用清洗前的 HTML 判型，所以还是判成图文；`addText` 用清洗后的空 HTML 存条目，标题回落成「图文」，`content.html` 为空。
4. 详情 iframe 在深色模式下是白底：srcdoc 文档没有声明 color-scheme，和深色的父页面不一致，Chromium 就给它画了不透明的白底。

## 改法（锁定）
A. `sanitizeHtml`
- 成对删除（连同内容）只针对 `script|style|iframe|object|embed|noscript|template`。
- `meta|link|base|input|button|form` 只删标签本身，保留标签之间的内容。其中 `form` 只删 `<form>` 和 `</form>` 两个标签，表单里的文字留下。
- 清洗后先算一次纯文本。如果清洗后的纯文本为空、清洗前有文字或剪贴板 `text` 有文字，就改用 `textToHtml(text)` 存，`rich` 记为 false，不让条目变空。
B. 详情页样式。mind 03:01 核对：`calendar.html` 的 CSP 是 `style-src 'self'`，srcdoc 继承父页面的 CSP，所以注入的内联 `<style>` 整段被拦。老板截图里的宋体黑字、白底就是这个原因。锁定改法：
- 把注入的样式写成 `calendar.js` 里一个固定常量，开头加 `:root{color-scheme:light dark}`、body 背景透明，其余沿用现有样式。
- 在 `calendar.html` 的 CSP `style-src` 后面加上这段常量的 `'sha256-…'` 哈希，不加 `'unsafe-inline'`，`script-src` 不动。
- 加一条单测：用常量现算的哈希必须和 CSP 里写的一致，防止以后改了样式忘了更新哈希。
C. 老条目：已经存空的条目没法恢复，不做迁移，也不做提示（老板 11-23 定：老数据是测试数据，可忽略）。

## 不改
判型顺序、标题长度规则、托盘和快捷键的收纳路径、0.1.57 的窗口内提示。
