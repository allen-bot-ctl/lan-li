# 0.1.61 帮阅：大模型设置独立，不再和 EasyLens 关联

来源：老板 2026-11-23 05:59 ET 真机验收 0.1.60。「我是会分发给其他用户使用的，没必要和 EasyLens 强关联；可以有必要的报错，例如未配置大模型等，然后我去配置就行了。」
范围：只改帮阅的大模型配置和相关提示，外加 0.1.60 发版核对时发现的两处界面问题。读取、提取、整理流程不动。

## 1. 去掉 EasyLens 关联
- 删除对 `~/.easylens/deepseek-api-key` 的读取和回落，以及 `easylensDir` 配置和相关 e2e 环境变量。
- 删除设置页「正在使用 EasyLens 的 DeepSeek Key」那一行。界面、文案、发版说明里不再出现 EasyLens。
- 老数据不迁移：之前靠 EasyLens Key 跑的，升级后显示「未配置大模型」，自己去设置里填（老板 2026-11-23 定：现有数据都是测试数据，升级后不报错就行）。
- `region-capture.js` 里的「参考 EasyLens」代码注释不算关联，不用动。

## 2. 设置页「帮阅」tab（改成通用的大模型配置）
```
帮阅
大模型
接口地址  [ https://api.deepseek.com              ]
模型      [ deepseek-chat                         ]
API Key   [ ••••••                                ]
          [保存] [测试连接] [删除 Key]
状态行：未配置 / 已配置 · deepseek-chat / 测试通过 / 测试失败：…
说明：支持 OpenAI 兼容接口（DeepSeek、OpenAI、通义、Kimi 等）。Key 只存在本机。
```
- 三个输入框同宽，标签列左对齐，字号 13px；状态行和说明 12px 灰字（设置页文字不小于 12px）。
- 接口地址：默认值 `https://api.deepseek.com`，只接受 https；保存时去掉末尾的 `/`。请求地址照旧拼 `{接口地址}/chat/completions`。不合法时框下一行红字「接口地址需要以 https:// 开头」。
- 模型：默认值 `deepseek-chat`，可手填任意字符串，不能为空。
- API Key：密码框；已保存时 placeholder 为「已保存，留空不修改」。存储照旧放 `userData/reader-api-key`，权限 0600，不进 preferences.json，不写日志，渲染进程拿不到明文。接口地址和模型存在 preferences 的 `reader.baseURL`、`reader.model` 里。
- 「测试连接」：用当前填的值（Key 留空就用已保存的）发一次最小请求（user 内容「ping」，`max_tokens:1`，超时 15 秒），成功显示绿字「测试通过」，失败按第 3 节的文案显示。测试期间按钮显示「测试中…」并禁用。
- 「删除 Key」：删掉 Key 文件，状态行变「未配置」。
- 状态行：没有 Key 显示「未配置」；有 Key 显示「已配置 · {模型}」。

## 3. 状态表（帮阅页和设置页）
| 情况 | 屏幕上出现什么 |
|---|---|
| 没有 Key，点「帮我读」 | 不入列；输入框下一行灰字「还没配置大模型，去设置 ›」，点了打开设置的「帮阅」tab |
| 打开帮阅页时没有 Key | 输入框下常驻同一行灰字提示，配置好后消失 |
| 接口 401/403 | 行内「API Key 无效，去设置 ›」；测试连接显示「测试失败：API Key 无效」 |
| 接口 404 | 「整理失败：接口地址或模型不对」；测试连接同文案 |
| 其他 HTTP 错误、网络错误、超时 | 和 0.1.60 一样：「整理失败：HTTP {code}」「整理失败：连不上接口」「整理失败：超时」 |
| 测试成功 | 绿字「测试通过」 |

## 4. 0.1.60 发版核对时发现的两处界面问题
- 帮阅列表页顶栏右侧补上「N 篇」计数（0.1.60 契约第 2 节，漏做了），样式和收纳页的计数一样。
