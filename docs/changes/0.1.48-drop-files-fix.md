# 0.1.48 致命修复：从 Finder 拖文件进接纳框全部失败（老板 00:49）

## 现象
任何文件拖进接纳框都显示「这个内容暂时收不进来」。

## 原因（mind 读代码判断，coder 先用日志确认）
- renderer/dropzone.js 在主世界拿到 `dt.files`，再经 contextBridge 交给 preload 的 `pathsOf` 调 `webUtils.getPathForFile`。File 对象跨 contextBridge 后不再是原生 File，`getPathForFile` 抛错被 catch 成 ''，files 变空 → classify 为 unsupported。
- e2e 都是直接调主进程 handleDrop 钩子，从没走过真实的 DOM drop → preload 路径，所以 227/95 全绿也没发现。

## 修法
1. 在 dropzone-preload.js 里直接监听 `drop`（preload 拿到的是原生 File），就地调用 `webUtils.getPathForFile`，把路径数组连同 html/text/uri-list 一起发给主进程；renderer 只负责界面状态，不再传 File。
2. 兜底：主进程收到 `text/uri-list` 里的 `file://` 时转成本地路径当文件处理。
3. 托盘图标直接放下（tray drop-files）路径保持不变，回归确认。
4. 失败日志写明 files/html/text/uriList 各自长度，方便以后定位。

## 验收
- F-C1 真机：从 Finder 拖 1 个、多个文件、1 个文件夹进接纳框，都成功并出现在列表。
- F-C2 e2e 新增一条走真实路径：在接纳框窗口派发带 DataTransfer 的 drop 事件，断言请求到达主进程且 files 非空（可用 E2E 钩子替换 getPathForFile 返回固定路径）。
- F-C3 `file://` uri-list 兜底单测。
- F-C4 发版前 mind 或 coder 在真实 macOS 上手动拖一次文件，截图贴群，再打 tag。
