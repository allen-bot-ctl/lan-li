# 0.1.59 收纳列表：悬停按钮不压标题；非文件不显示「在 Finder 中显示」

来源：老板 2026-11-23 03:44 ET 真机反馈（截图：悬停时「在 Finder 中显示 / 复制 / # / ×」压在「栏历 v0.1.57 已出包…安装包」上，文字从按钮底下透出来）。

## 根因
1. `.inbox-row-actions` 是绝对定位，叠在行上，本身没有底色；标题区 `.inbox-row-body` 的宽度不随按钮变化，所以长标题从按钮下面露出来。时间只是 `visibility:hidden`，还占着位置。
2. `buildInboxRow` 对所有类型都加了「在 Finder 中显示」，右键菜单也是。图文、文字、链接、剪贴板图片、框选图片都存在栏历自己的数据目录里，在 Finder 里打开的是内部文件夹，对用户没有意义。

## 改法（锁定）
A. 悬停时标题让位
- 行在 `mouseenter` 和 `focusin` 时，把按钮组的实际宽度写进行上的 CSS 变量：`row.style.setProperty('--acts-w', acts.offsetWidth + 'px')`。按钮组是 `visibility:hidden`，宽度照样能量到。
- 悬停或聚焦时：`.inbox-row-time` 和 `.inbox-row-thumb` 改成 `display:none`；`.inbox-row-body` 加 `padding-right: calc(var(--acts-w) + 8px)`。标题和副标题都按现有规则在按钮左边 8px 处出省略号。
- 「原文件已移动」的行按钮常显，同样适用这条：常态就让位。
- 不加渐隐遮罩，不改按钮样式和间距。
B. 「在 Finder 中显示」只给文件类
- 只有 `m.type === 'file'` 且文件没有丢失时，悬停按钮和右键菜单里才有「在 Finder 中显示」。
- 其他类型的悬停按钮是「复制 / # / ×」，右键菜单只有「删除这条」。
- 主进程 `reveal(id)` 对非文件类直接返回 false，不打开 Finder。
- 文件丢失时的「重新指定原文件…」不变。

## 不改
点行打开详情、复制、标签、删除、0.1.57 的窗口内提示、0.1.58 的详情样式。

## 验收
- S1 e2e：收一条 60 字的图文，悬停该行。量 `.inbox-row-title` 的 `getBoundingClientRect().right`，必须不超过 `.inbox-row-actions` 的 `left - 8`；标题 `scrollWidth > clientWidth`（出了省略号）。
- S2 e2e：文件类悬停有 4 个按钮，顺序是「在 Finder 中显示 / 复制 / # / ×」。图文、文字、链接、图片类悬停只有 3 个按钮，没有 `.inbox-act-reveal`。
- S3 e2e：非文件类右键菜单没有 id `inbox-reveal`，文件类有。对非文件类调 `inbox:reveal` 返回 false，`e2eOpenCalls` 不增加。
- S4 截图：`59-row-hover-long-dark.png`、`59-row-hover-long-light.png`（长标题图文行悬停），`59-row-hover-file-dark.png`（文件行悬停，4 个按钮）。
- M1 老板真机：长标题悬停，标题在按钮左边出省略号；图文行没有「在 Finder 中显示」。
