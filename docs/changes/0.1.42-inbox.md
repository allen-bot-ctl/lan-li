# 栏历 0.1.42「收纳」方案（mind，2026-11-19 21:10 纽约时间）

需求：任何东西拖进栏历即存，当备忘/收纳箱。分两段交付：**A 段**＝接纳框 + 落盘 + 最简列表；**B 段**＝分类、标签、检索、日期视图。样稿：同目录 `demo.html` / `demo-2x.png`。

## 一、触发方式（已定）
- 拖拽经过菜单栏时钟图标 → `tray.on('drag-enter')` → 在图标正下方弹出接纳框真窗口（无边框、置顶、不抢焦点，`showInactive()`）。
- 「靠近菜单栏就出」本版不做：需要 NSEvent 全局鼠标监听 + 拖拽剪贴板 changeCount（Dropover/Yoink/boring.notch 做法），Electron 纯 JS 拿不到，要原生模块。
- 接纳框出现后，悬停开日历的逻辑暂停；拖拽结束（`drag-end`）或离开框 1.2s 后收起。
- 图标本身也能直接接收：`drop-files`/`drop-text` 落在图标上同样保存（兜底，用户没移到框里也不丢）。

## 二、接纳框（A 段）
尺寸 240×120，圆角 12，毛玻璃底同日历窗口；距图标下沿 6px，水平居中于图标，贴屏幕右缘时左移。
| 状态 | 触发 | 表现 | 文案 |
|---|---|---|---|
| 1 出现（空闲） | drag-enter 图标 | 虚线框 + 收纳图标 | 「拖到这里，放进收纳」 |
| 2 进入高亮 | 渲染进程 dragenter 框 | 实线橙框、底色加深、图标上跳、显示类型 | 「松开即保存 · 3 个文件」 |
| 3 保存成功 | drop 写盘完成 | 绿勾，1.2s 后收起 | 「已收纳 3 项」＋小字「点开查看」 |
| 4 不支持/失败 | 无可识别数据、写盘失败、超限 | 红色描边，2s 后收起 | 「这个内容暂时收不进来」/「保存失败，磁盘空间不足」 |
- 最长文案「保存失败，磁盘空间不足」13 字 × 13px ≈ 170px < 框内可用 208px。
- 点「点开查看」或成功态本身 → 打开日历窗口并 `sendPanel('inbox')`。

## 三、取数规则（渲染进程 drop）
| 拖入内容 | 判定 | 存为 |
|---|---|---|
| Finder 文件/文件夹（非图片） | `dataTransfer.files` + `webUtils.getPathForFile` | **文件**：软链接（A 段；Finder 替身挪到 B 段实测） |
| 图片文件（png/jpg/heic/gif/webp） | 扩展名/MIME | **图片**：复制原文件 |
| 浏览器拖图片 | `text/uri-list`/`text/html` 里的 `<img src>`；有 files 用 files | **图片**：主进程下载/解码 data: 后存副本，记来源 URL |
| 选中的富文本 | 有 `text/html` | **文字**：清洗后的 content.html，内嵌图片落成单独文件 |
| 纯文字 | 只有 `text/plain` 且不是单个 URL | **文字**：content.html（转义包 `<p>`） |
| 链接 | `text/uri-list` 或纯文本是单个 http(s) URL | **链接**：URL + 标题（拖拽数据里的标题，取不到用域名） |
- Electron 31 里 `File.path` 已标记弃用（32 删除），统一走 preload 的 `webUtils.getPathForFile`。

## 四、落盘（A 段）
根目录 `~/Library/Application Support/栏历/inbox/`（即 `app.getPath('userData')/inbox`）。每条一个目录：
```
inbox/
  <id>/                       id = 20261119-211034-ab12（时间+4位随机）
    meta.json
    文件： 原名.symlink（A 段软链接）
    图片： original.<ext>  thumb.jpg(≤320px)
    文字： content.html  assets/img-1.png …
    链接： （只有 meta.json）
```
meta.json：
```json
{ "id":"20261119-211034-ab12", "type":"file|image|text|link", "title":"季度报告.pdf",
  "createdAt":"2026-11-19T21:10:34-05:00", "tags":[], "sourcePath":"/Users/x/Desktop/季度报告.pdf",
  "sourceUrl":null, "size":482133, "ref":"symlink|copy"（B 段可能加 alias）, "missing":false,
  "preview":"前 120 字纯文本摘要", "schema":1 }
```
- 文件（A 段，PM 21:05 定）：`fs.symlink` 建软链接，meta 记原路径 `sourcePath`。Finder 替身（osascript）挪到 B 段再实测。
- 写盘先写 `<id>.tmp/` 再 rename，保证不出半截条目。单次最多 50 项，单张图片 ≤ 50MB，超出走状态 4。
- 列表读取：启动时扫描各 `meta.json`；B 段再加 `index.json` 作缓存（可随时由 meta 重建）。

## 五、原文件移动/删除
- 打开列表或点开时用 `fs.realpath` 检查软链接；解析失败就标 `missing:true`，整行置灰。
- 置灰条目副标题「原文件已移动或删除」，操作只剩「删除这条」「在 Finder 中显示收纳目录」；B 段再加「重新指定原文件…」。
- 图片、文字、链接是自存的，不受影响。

## 六、A 段：最简列表
- 入口：顶栏新增「收纳」图标（检查更新左侧，24px 圆按钮），`sendPanel('inbox')`；成功态点开也到这里。
- 内容区 400px 高整块列表，时间倒序，每行 44px：左 28px 类型图标/图片缩略图，中间标题（单行省略）+ 副标题（文件大小·来源／正文摘要／域名），右侧时间「21:10」「昨天」「11月17日」。
- 点一行 = 打开：文件用 `shell.openPath`，图片用系统预览，文字在面板内展开富文本，链接 `shell.openExternal`。行右键菜单：在 Finder 中显示、删除。
- 空状态：「把文件、图片、文字或链接拖到菜单栏时钟上，就会收在这里」。

## 七、B 段：分类、标签、检索、日期视图（样稿 d，mind 21:2x 细化）
- 面板顶部一行：搜索框（⌘F 聚焦，Esc 清空）+ 类型筛选胶囊「全部/文件/图片/文字/链接」，单选。
- 第二行：标签胶囊，按使用次数降序，最多 6 个，其余收进「+N」（点开是下拉列表）；标签可多选，多选是「同时带这些标签」。类型、标签、日期、搜索四种条件叠加（与）。
- 标签：存在 meta.json 的 `tags: string[]`；单条「#」按钮弹小输入框，输入时联想已有标签，回车添加，单个最长 8 字，每条最多 5 个；标签胶囊右键「删除这个标签」= 从所有条目移除。不做标签改名、不做颜色。
- 日期：每条以 `createdAt`（收进来的时间）为日期属性，不可改。分组「今天/昨天/本周（周一起）/本月/更早按月，如「10月」」。
- 搜索：输入即筛，大小写不敏感，命中标题、正文纯文本、文件名、来源域名、标签；命中词高亮。数据来自内存里的 index.json，index 丢失可从各条 meta.json 重建。
- 单条操作（悬停出现在行右侧）：在 Finder 中显示、复制（文件复制路径/图片复制图片/文字复制富文本/链接复制 URL）、#加标签、×删除（无二次确认，底部 toast「已删除 · 撤销」5 秒）。
- 原文件失联：继续用软链接，不建 Finder 替身（不弹授权）；置灰条目加「重新指定原文件…」，选中后重建软链接。
- 日历联动：有收纳的日期在月历日期数字下方显示灰色 4px 圆点；点日期旁的圆点或在收纳面板外点该日期都不跳转，只有在收纳面板打开时点月历日期才筛到当天，顶部出现「11月19日 ×」胶囊。
- 空结果：「没有符合条件的收纳」+「清除筛选」按钮。
- 最长文案：5 个类型胶囊 + 搜索框在 560px 内放得下；标签 8 字超出省略。

## 八、首版不做
「靠近就出」的全局检测；云同步；拖出收纳到其他应用；编辑富文本；OCR/全文搜文件内容；多窗口；回收站（删除即删条目目录，不动原文件）。

## 九、需老板拍板（≤3）
1. **删除条目时是否同时删除图片/文字的自存内容？** 推荐：是（直接删条目目录，原文件永远不动）。
2. ~~Finder 替身授权~~：B 段也不建替身，改用「重新指定原文件…」，不需要拍板。
3. **B 段日历联动的小圆点是否和现有节假日/事件标记共存？** 推荐：用灰色 4px 点放在日期数字下方，和现有标记不冲突。

## 十、验收草稿
A 段
- A-C1 拖文件到时钟图标，≤300ms 弹出接纳框（状态 1），离开 1.2s 收起。
- A-C2 拖入框内出现状态 2，文案显示条目数与类型。
- A-C3 松开后 1s 内出现状态 3，`inbox/<id>/meta.json` 存在且字段齐全。
- A-C4 文件生成软链接指向原文件，meta 的 `ref` 为 symlink 且 `sourcePath` 等于原路径。
- A-C5 图片存副本 + thumb.jpg；浏览器拖图（http 与 data:）都能存。
- A-C6 富文本存 content.html，内嵌图片在 assets/ 下且 html 引用相对路径；不含 `<script>`/事件属性。
- A-C7 链接存 URL 与标题，纯文本单 URL 判为链接。
- A-C8 空数据/写盘失败显示状态 4；不留 `.tmp` 目录。
- A-C9 列表时间倒序，点开四类各走对应打开方式；原文件移走后条目显示「原文件已移动或删除」。
B 段
- B-C1 类型筛选与标签筛选可叠加；B-C2 搜索命中标题/正文/文件名/标签，200 条内 <50ms。
- B-C3 按今天/昨天/本周/更早分组正确（跨周一边界测试）。
- B-C4 加标签、复制、在 Finder 中显示、删除可用，删除不影响原文件。
- B-C5 有收纳的日期显示小点，收纳面板打开时点日期筛到当天，× 取消。
- B-C6 删除后 5 秒内可撤销；标签每条≤5、单个≤8 字；index.json 删除后重启可重建。
- B-C7 失联条目「重新指定原文件…」后恢复正常显示。
- B-C8 e2e 截图补 4 张并上传到 Release：`40-inbox-dropzone-idle.png`、`41-inbox-dropzone-over.png`（橙框+件数）、`42-inbox-list.png`（四类各一条+一条失联）、`43-inbox-panel-filtered.png`（B 段带搜索词、类型和标签筛选）。
