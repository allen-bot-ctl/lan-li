# 0.1.52 固定签名身份，授权一次长期有效（老板 02:45：点 + 号是敷衍，要解决到位）

## 目标
普通用户不需要手动点「+」添加栏历；授权一次后，以后每次升级都不用再授权。

## 根因
- 「列表里没有栏历」：0.1.51 已修。按 ⌃⌥S 时会先真正截一次屏，系统随即弹出授权框，并把栏历加进列表。
- 「升级后要重新授权」：package.json 里 `mac.identity` 是 `"-"`，也就是临时签名。临时签名的指定要求（DR）就是这一版的 cdhash，每次构建都会变。系统的隐私权限（TCC）按 DR 认应用，所以每次升级都会被当成一个新应用，授权失效。
- 证据：[Snapzy 自签证书文档](https://github.com/duongductrong/Snapzy/blob/94d58ce9/docs/SELF_SIGNED_CERT.md)、[hermes-agent PR 67357](https://github.com/NousResearch/hermes-agent/pull/67357)（在 macOS 26.5 上验证过）、[tinycast 签名文档](https://github.com/reycn/tinycast-macos-15/blob/main/docs/signing.md)。三份互相独立，结论一致：只要每版都用同一张自签代码签名证书，DR 就会变成 `identifier + certificate leaf`，升级后授权保留。

## 改法（唯一方案）
1. 生成一张自签代码签名证书，名称「LanLi Self-Signed」，有效期 10 年，用途 codeSigning。导出为 p12，存进 GitHub Secrets（`LANLI_SIGN_P12`、`LANLI_SIGN_PASSWORD`）。私钥不进仓库。p12 只放在 GitHub Secrets 和 coder 本机各一份（PM 02:54 定），coder 本机那份就是备份；丢了只能换证书，所有用户要重新授权一次。
2. release.yml 增加两步：把证书导入临时 keychain；用 electron-builder 以这个身份签名，包括 `--deep` 签内部的 helper。`hardenedRuntime` 保持 false，不做公证。
3. 「Verify ad-hoc signature」这一步改成「Verify stable signature」，要求三条全部满足：
   - `codesign -dv` 输出 `Authority=LanLi Self-Signed`，不再是 `Signature=adhoc`；
   - `codesign -d -r-` 的 designated 里有 `certificate leaf`，没有 `cdhash`；
   - `codesign --verify --deep --strict` 通过。
4. 应用内更新继续走 `mac-self-update.js`：sha256 校验加 ditto 解压，不依赖签名。不切到 Squirrel.Mac。确保 0.1.51（临时签名）升到 0.1.52（自签）能在应用内完成。
5. 说明卡删掉「列表里没有栏历？点 +…」这行小字，其余文案不变。57 号截图深浅两套重拍。
6. `main.js` 199、400 行附近有按「未签名」降级的逻辑（开机自启动）。签名换了以后要复核这两处，行为不能退化。

## 验收

- S-C2 CI：同一个 commit 构建两次，两次 `codesign -d -r-` 输出完全相同。
- S-C3 e2e：说明卡里没有「+」字样。57 号截图深浅两套。
- S-C4 既有 e2e 和单测全部通过（TZ=UTC）。
- 真机（老板）：
  - ① 0.1.51 在应用内升到 0.1.52 能成功；
  - ② 在 0.1.52 上授权一次屏幕录制；
  - ③ 下一版（0.1.53）升级后按 ⌃⌥S 能直接框选，不再弹授权。

## 已知限制
- 从临时签名换到固定签名，第一次需要再授权一次，之后就不用了。
- 自签证书不能过 Gatekeeper：首次安装 dmg 时还是要右键打开，这和现在一样。要彻底去掉这一步，得用苹果开发者证书（年费 99 美元）加公证，这需要老板决定，本版不做。
