# 0.1.64 没配大模型时锁定提示词 · 「AI 改提示词」弹框

来源：老板 2026-11-23 23:15 两条反馈（附截图：设置 › 帮阅 › 提示词）。契约 mind；PM 有分歧时在群里一句话对齐，由 PM 定。
本版不涉及数据迁移。不出 demo：弹框沿用 0.1.63 退出确认框的遮罩和卡片样式，只多了输入框和结果框，用 CI 深浅两套截图验收。

## 1. 没配大模型时，提示词不能改

「已配置」的判断和帮阅页完全一样：`getReaderConfig().ready`（有没有存 API Key）。「测试连接」失败不算未配置，不锁。

- 锁定时：
  - 提示词框 `#reader-prompt` 设为 `readOnly`（还能滚动、选中复制，不能输入），透明度 .45，光标 default。
  - 「保存」「恢复默认」「AI 改提示词」三个按钮 `disabled`，透明度 .45，光标 default，悬停不变色。
  - 按钮行下面新增一行 `#reader-prompt-lock`：「先在上面配置大模型，才能修改提示词。」12px，次级色，左缩进和 `.reader-prompt-hint` 一样（62px），上边距 6px。原来那行说明 `.reader-prompt-hint` 照常显示在它下面。
- 解锁时：以上全部恢复，`#reader-prompt-lock` 隐藏。

| 状态 | 提示词框 | 三个按钮 | 锁定提示 |
|---|---|---|---|
| 没有 API Key（含首次安装） | 只读、变淡，显示已保存的提示词（没存过就是默认提示词） | 置灰 | 显示 |
| 在上面保存了 Key | 立即解锁，不用切页 | 可用 | 隐藏 |
| 点「删除 Key」 | 立即锁定，框里换回已保存的提示词（没保存的改动丢弃） | 置灰 | 显示 |
| 有 Key 但「测试连接」失败 | 不锁 | 可用 | 隐藏 |

## 2. 「AI 改提示词」

### 2.1 入口

- 提示词按钮行：「保存」「恢复默认」后面加第三个按钮「AI 改提示词」，样式和前两个一样（nav-pill）。错误文字 `#reader-prompt-err` 仍跟在最后。
- 没配大模型时置灰（见第 1 条）。

### 2.2 弹框（窗口内弹层，不用系统对话框）

- 遮罩、卡片圆角、内边距、背景、阴影都和 0.1.63 的退出确认框一样（`rgba(0,0,0,.35)`，圆角 12px，内边距 20px，`var(--sheet-bg)`）。卡片宽 440px，最大高度 `calc(100% - 32px)`。深浅两套都要看。
- 从上到下：
  1. 标题「AI 改提示词」：15px，semibold，正文色。
  2. 说明「写一句想怎么改，AI 只改动现行提示词里和要求有关的部分。」：13px，次级色，行高 1.6，上边距 8px。
  3. 需求框 `#prompt-ai-input`：多行，高 3 行（13px，行高 1.5），最多 500 字，样式和 `#reader-prompt` 一样。占位文字「比如：核心要点只留 5 条，每条不超过 20 字」。上边距 12px。
  4. 结果区 `#prompt-ai-result`（有结果才出现）：上边距 12px。先是一行「新版提示词」（12px，次级色），下面是只读文本框：13px，行高 1.5，`white-space: pre-wrap`，背景 `var(--chip)`，圆角 6px，内边距 6px 8px，最大高 150px，超出滚动。不能在这里编辑；用了新版以后可以在设置页的提示词框里改。
  5. 错误行 `#prompt-ai-err`（出错才出现）：12px，`#d9534f`，上边距 8px。
  6. 按钮行：右对齐，间距 8px，上边距 16px。按钮高 30px，左右内边距 16px，13px。主按钮（「生成新版」「再试一版」「使用新版」里最右边那个）用 `var(--accent)` 实底白字；其他是次级 nav-pill。
- 改的是哪一版：打开弹框那一刻提示词框里的内容（包括还没保存的改动）；框是空的就用默认提示词。同一次弹框里「再试一版」也一直从这一版改，不在上一次的新版上叠加。
- 每次打开，需求框都是空的，焦点在需求框里。

### 2.3 状态表

| 状态 | 弹框里 | 按钮（从左到右） |
|---|---|---|
| 刚打开 | 需求框空，有焦点；没有结果区 | 取消 · 生成新版（需求为空时置灰） |
| 第一次生成中 | 需求框只读 | 取消 · 生成中…（置灰） |
| 生成成功 | 出现结果区，显示新版全文；需求框可以接着改 | 保持原版 · 再试一版 · 使用新版（主按钮） |
| 再试一版生成中 | 结果区保留上一版，需求框只读 | 保持原版 · 生成中…（置灰） · 使用新版（置灰） |
| 第一次就失败 | 显示错误行，需求框可以改 | 取消 · 生成新版 |
| 再试一版失败 | 显示错误行，结果区保留上一版 | 保持原版 · 再试一版 · 使用新版（用结果区里这一版） |
| 点「取消」「保持原版」或按 Esc | 弹框关闭，提示词不变；正在进行的请求中止，结果丢弃 | — |
| 点遮罩空白处 | 不关（防止误点丢掉已生成的结果） | — |
| 点「使用新版」 | 用新版覆盖现行提示词并保存（走现有 `saveReaderPrompt`，和点「保存」同一套校验）；提示词框换成新版；弹框关闭；toast「提示词已更新」 | — |
| 「使用新版」保存失败 | 弹框不关，错误行显示保存返回的错误 | 不变 |
| 弹框开着时窗口被隐藏 | 弹框关闭，请求中止，不保存；下次打开设置页不带弹框 | — |

- 键盘：需求框里回车换行；⌘↩ 等于点当前的「生成新版」或「再试一版」（置灰时无效）。Esc 只关弹框，不会同时退出设置页（和 0.1.63 退出确认框同一个处理方式）。
- 已经整理好的文章不受影响，新提示词只对之后的「整理」「重新整理」生效。想回到原来的样子，可以点「恢复默认」。

### 2.4 请求（主进程发，Key 不进渲染进程）

- 走现有 `reader-llm.js` 的 `complete()`：`max_tokens` 4096，超时 90 秒，非流式，和整理文章一样。
- system 原文（一字不改）：

```
你是提示词编辑。用户消息里有两段：<<<现行提示词>>> 和 <<<修改需求>>>。请按修改需求改写现行提示词：需求涉及的地方照改，需求没提到的部分保持原文不变。只输出改好后的完整提示词本身，不要解释，不要加前言或结尾，不要用代码块包起来。这段提示词是给阅读助手整理文章用的，文章正文和安全规则由程序另外附加，不要写进提示词。
```

- user 模板（`{prompt}` 是 2.2 说的那一版，`{request}` 是需求框内容去掉首尾空白）：

```
<<<现行提示词>>>
{prompt}
<<<结束>>>

<<<修改需求>>>
{request}
<<<结束>>>
```

- 返回处理：去掉首尾空白；如果整段被一对 ``` 代码块包着（可带语言名），去掉这对代码块。
- 整理文章时 `buildSystem` 照旧在提示词后面附加固定的安全说明，AI 改出来的提示词也盖不掉它。

### 2.5 错误文案（显示在 `#prompt-ai-err`）

| 情况 | 文案 |
|---|---|
| HTTP 401 / 403 | 生成失败：API Key 无效 |
| HTTP 404 | 生成失败：接口地址或模型不对 |
| 其他 HTTP 错误 | 生成失败：HTTP {状态码} |
| 连不上 | 生成失败：连不上接口 |
| 超时 | 生成失败：超时 |
| 返回格式不对 | 生成失败：返回格式不对 |
| 返回为空（含去掉代码块后为空） | 生成失败：大模型没有返回内容 |
| 新版超过 4000 字（`MAX_PROMPT_CHARS`） | 生成失败：新版超过 4000 字，再试一版 |

## 3. 验收

- R1：第 1 条状态表每一行都有 e2e：没有 Key 时提示词框只读、三个按钮置灰、显示锁定提示；保存 Key 后不切页立即解锁；删除 Key 后立即锁定。截图 64-prompt-locked，深浅各一套。
- R2：2.3 状态表每一行都有 e2e（大模型用 e2e 现有的假接口）：生成、再试一版、使用新版后 `reader-prompt.txt` 内容等于新版、保持原版和 Esc 后文件不变、点遮罩不关、失败两种情况的按钮、窗口隐藏后再打开不带弹框。截图 64-prompt-ai-input（刚打开）和 64-prompt-ai-result（生成成功），深浅各一套。
- R3：单测：请求的 system 和 user 和 2.4 原文逐字一致；「再试一版」用的仍是打开时那一版提示词；代码块剥离；超过 4000 字报错；2.5 每条错误文案。
- R4：单测和 e2e 全量通过。
- M1（老板真机）：删掉 Key 后提示词改不了；配好 Key 后点「AI 改提示词」，写「核心要点只留 3 条」，生成后点「使用新版」，再整理一篇文章，核心要点是 3 条。
