# 0.1.56 标签：弹层加宽 + 默认标签 + 标签管理（ID 化）

老板原话（2026-11-23 00:45 ET）：加标签弹层太紧凑；初装默认带「备忘、重要、临时」；标签可管理：可删（默认的也能删，删标签不影响数据）、可新增（查重，不许重复）、可改名（只改显示值，用标签 ID，数据不用改）。
demo：不出（静态尺寸 + 数据结构，契约能说清）。

弹层宽 = 224（200 + 2×12），右缘与「#」按钮右缘对齐，不超出窗口。深浅两套。

## B. 标签库（数据）
- 新文件 `<inbox root>/tags.json`：`{ version:1, tags:[{ id:'t_<随机8位>', name:'备忘', createdMs }] }`。
- 条目 `meta.tags` 从「名字数组」改为「ID 数组」。显示、筛选、检索一律通过 ID 查名字。`#名字` 检索照旧可用。
- **首次启动**（没有 tags.json）：建库，写入 备忘、重要、临时 三个，顺序如此；老用户升级同样补这三个（重名则复用，不重复建）。只在建库那一次补；之后用户删掉默认标签，不会再补回来（判断依据：tags.json 已存在就不补）。
- **备份**：迁移前在每条目录里把 `meta.json` 复制为 `meta.json.bak-0156`，已存在则不覆盖（index.json 是可由 meta.json 重建的缓存，不单独备份）。迁移中任一步出错：停止、保留原数据不动、记日志，收纳照旧按老格式可读，下次启动重试。
- **迁移**：老条目里的字符串标签逐个查库，没有就新建，再把 meta.tags 换成 ID；迁移幂等，重跑结果不变；index.json 随之重建。
- **查重规则**（新增、改名、弹层输入共用）：去首尾空格、去开头的 #、NFKC（全角转半角）、英文不分大小写后比较。长度 1–8 字不变，每条最多 5 个不变。
- 弹层里输入一个已存在的名字（按查重规则）→ 直接给本条加上那个已有标签，不报错、不新建。

## C. 标签管理（设置页新增「标签」tab，放在「世界时钟」和「升级」之间）
| 操作 | 行为 |
|---|---|
| 列表 | 每行：`#名字` + 「N 项」（使用条数）+ 改名、删除按钮；默认三个和自建的一视同仁，按创建顺序 |
| 新增 | 顶部输入框 +「添加」（回车同效）；重复时输入框下红字「已有标签 #名字」，不添加 |
| 改名 | 点改名 → 该行变输入框，回车或失焦保存，Esc 取消；只改 tags.json 的 name，不碰任何 meta.json；与其它标签重复时红字「已有标签 #名字」不保存；和自己原名相同视为未改 |
| 删除 | 点删除 → 该行就地变成「删除 #名字？N 项会去掉这个标签，条目本身保留」+「取消」「删除」（红）；确认后从库里删掉，并从所有条目的 meta.tags 去掉这个 ID；条目一个不少 |
| 收纳页同步 | 收纳页顶部标签筛选条、条目上的标签、右键「删除这个标签」都走同一套 ID 逻辑；右键删除 = 管理页删除，同样先确认 |
| 空库 | 全删光后列表显示「还没有标签，在上面添加一个」 |
